# Публикация двух сервисов «Есть тема»

Актуально на 21.11.2026: оба сервиса размещены через ZIP/GitRelax в RelaxDev. Сайт: https://got-a-topic-frontend.isodomain.tech/; API: https://got-a-topic-api.isodomain.tech. Новый дизайн и изображение проверены после исправления копирования `public` в runner. GitHub и GitRelax — разные пути доставки; новый push в GitHub не подтверждает редеплой. Остальные пошаговые инструкции ниже относятся к настройке среды. Постоянство диска backend при полном редеплое не подтверждено.


## Историческая подготовка публикации (до развёртывания)

Два локальных репозитория готовы к проверке и публикации. Публичные репозитории и сервисы не считаются созданными до проверки их адресов. Пользователь создал публичные `Fealserg/got-a-topic-backend` и `Fealserg/got-a-topic-frontend`. Оба origin подключены, main успешно отправлены. Прежняя ошибка GitHub API 401 не препятствовала стандартному git push. Авторизация в RelaxDev подтверждена пользователем ссылкой на профиль; управлять браузером из текущей сессии не удалось.

## 1. GitHub

Предлагаемые имена: `Fealserg/got-a-topic-backend` и `Fealserg/got-a-topic-frontend`, публичные, без стартовых файлов. В текущих папках уже есть Git-история и код. Подключение remote не требует копировать код поверх нового клона:

```sh
git -C backend remote add origin https://github.com/Fealserg/got-a-topic-backend.git
git -C backend push -u origin main
git -C frontend remote add origin https://github.com/Fealserg/got-a-topic-frontend.git
git -C frontend push -u origin main
```

Если origin уже существует, сначала проверить `git remote -v`, не менять его молча. Если владелец/имя отличаются, использовать реальные URL. Для push нужна авторизация Git, а не только браузерная сессия. Секреты не передавать в чат и не хранить в документах проекта.

## 2. Backend в RelaxDev

Создать приложение из backend-репозитория в режиме «Свой Dockerfile». Платформа сама задаёт PORT. Один экземпляр и один worker. Подключить постоянный диск к `/data`; проверить права пользователя приложения на запись.

Переменные:

- `DATABASE_URL=sqlite:////data/pereryv.db`;
- `FRONTEND_URL=https://<адрес-фронтенда>`; несколько разрешённых origin разделять запятой;
- `COOKIE_SECURE=true`;
- `DEMO_MODE=false` для пилота;
- `ADMIN_USERNAME` и уникальный `ADMIN_PASSWORD` (12+ символов) для первоначального создания организатора через seed.

Docker запускает Alembic, справочник тем и uvicorn. Для временной презентационной среды демо-аккаунты создавать явно `python -m app.seed --demo` и задавать DEMO_MODE=true. Не смешивать реальных участников с известными публичными паролями демо.

Проверить `https://<backend>/api/health` и `/api/docs`. Для интерактивного Swagger удобнее домен frontend: Origin должен быть разрешён, Authorize — `pereryv`.

## 3. Frontend в RelaxDev

Создать приложение из frontend-репозитория, также «Свой Dockerfile». Задать `API_BASE_URL=https://<адрес-бэкенда>`: только HTTP(S) origin, без `/api`, пути, query, user/password и завершающих пробелов. В production параметр обязателен.

Используется standalone Next.js. Сервер читает `process.env['API_BASE_URL']` при запросе, а не во время сборки. Значение `auto-generated-stub-for-build` и неверные URL безопасно отклоняются с JSON 502. Все браузерные API-запросы идут на `/api/*` своего домена.

## 4. Приёмка после размещения

1. GET `/api/health` на обоих доменах возвращает 200 и JSON.
2. `/api/docs` и `/api/openapi.json` открываются через frontend.
3. Регистрация, вход и повторное открытие профиля работают с Secure/HttpOnly cookie.
4. Два участника публикуют профили, видят объяснимое совпадение, отправляют и принимают приглашение.
5. Повторное принятие не создаёт дубль; конкурентные приглашения не создают пересечение; отмена освобождает время.
6. Прошедшие слоты не предлагаются, после окончания доступна оценка.
7. Перезапуск backend сохраняет профиль, сессию и встречу на постоянном диске.
8. Мобильный экран, диалог, ошибки полей и предупреждение о несохранённом профиле проверены в браузере.
9. Доступ к журналам есть; JSON-запись содержит маршрут, статус, длительность, размер и код ошибки, без персональных данных. Uvicorn access log выключен, чтобы не дублировать необработанные URL.

Не подменять эти проверки успешными локальными тестами. Размещённое приложение должно оставаться доступным во время проверки жюри.
