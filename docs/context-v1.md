# Контекст v1 · после реализации и автоматических проверок

Дата: 20.11.2026. База — context-v0.md. Изменения отражают реализованное приложение, не результаты продуктового пилота.

## Что реализовано

Два локальных Git-репозитория: frontend и backend. Профили с видимостью, структурированные темы запроса/опыта и свободное время; подбор с причинами; приглашения, принятие/отказ/отмена; собственная обратная связь после встречи. Панель организатора показывает агрегаты без демо и позволяет добавлять будущие непересекающиеся интервалы.

Пароли scrypt, HttpOnly сессии, CSRF-заголовок и проверка Origin. Профиль регистрируется скрытым. Публикация требует тему и будущую доступность. Личные контакты не собираются; разговор возможен по теме, времени и точке встречи.

## Принятые уточнения

Next.js работает в standalone-режиме, вместо статического export/nginx из примера. HTTP-прокси в серверном route handler читает API_BASE_URL при запросе; FastAPI остаётся отдельным сервисом и единственным местом бизнес-правил. Это позволяет использовать отдельные репозитории и настраивать origin backend при запуске frontend.

Важное правило гонок: accepted резервирует время обоих участников в одной SQLite-транзакции; pending ничего не резервирует. Другие конфликтные приглашения переходят в conflict. Слот при отмене освобождается, но старые конфликтные приглашения автоматически не возвращаются. Часовое ограничение повторного приглашения продолжает действовать.

Удаление профиля каскадно удаляет связанные встречи и оценки у обеих сторон. Для публичного продукта возможен иной жизненный цикл с обезличиванием истории; текущая логика явно показана в подтверждении удаления.

## Что проверено и что остаётся неизвестным

25 API-тестов прошли, включая конкурентное принятие, идемпотентность, доступ, удаление, обратную связь, исключение демо и сохранность после смены соединений. Миграция применена и Alembic не находит расхождений. Пройден smoke на демо-БД: здоровье, справочник, вход и подбор. 10 тестов прокси, TypeScript strict и production build прошли.

Живые браузерные сценарии и контейнеры не проверены: локальное открытие порта запрещено EPERM, Docker CLI отсутствует. Код E2E подготовлен, не запускался. GitHub remote, RelaxDev и публичные URL не настроены. Наличие локальной production-сборки не подтверждает работоспособность размещения.

Пилот с реальными людьми не проводился. Проблема, размер эффекта, точка встречи и реальные перерывы остаются непроверенными. Организаторская помощь с анонсом и набором добровольцев необходима.

## Доработки после сверки с материалами организаторов

Было → стало: схемы ответов OpenAPI `{}` → явные Pydantic-контракты; непредвиденный plain-text 500 → безопасный JSON; 429 без времени ожидания → Retry-After; невалидационный backend origin → проверка HTTP(S) origin и конфигурации платформы внутри try/catch; общие ошибки формы → сообщения возле полей; потеря несохранённого профиля → подтверждение ухода. Добавлены отдельные AGENTS.md и набор использованных заданий в каждом репозитории.

CI описывает проверки контейнеров, перезапуска и Chromium/WebKit; эти проверки пока не запускались на GitHub. Внешние блокеры: сохранённая авторизация GitHub API даёт 401, управление браузером недоступно, локальный bind порта запрещён EPERM, Docker CLI отсутствует. Пользователь создаёт репозитории самостоятельно и подтвердил наличие авторизации RelaxDev. До проверки результатов ни push, ни деплой не считаются выполненными.

## Подтверждение на GitHub после публикации

Созданы и опубликованы два публичных репозитория got-a-topic-backend и got-a-topic-frontend. Оба CI завершились успешно: API, proxy, типы, сборка, браузерные сценарии, два контейнера, сохранность сессии после рестарта. Проверенные commit и ссылки — ci-verification.json. Прежние ограничения относились к локальному sandbox; проверка перенесена на GitHub runner. Production RelaxDev и пилот с реальными участниками всё ещё ожидают настройки.
