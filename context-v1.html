Контекст v1 — итог реализации «Есть тема»

Актуализировано 21 ноября 2026 года после публикации утверждённого дизайна и проверки основного сценария на production.

1. Бизнес-потребность

Участнику конференции нужен собеседник, с которым можно обсудить профессиональную задачу. До знакомства неизвестны интересы, опыт и доступность другого человека; короткий перерыв легко проходит без полезного разговора. Это продуктовая гипотеза: интервью и сравнительный пилот не проводились.

«Есть тема» связывает запрос, опыт и свободное время. Пользователь указывает, что хочет обсудить и чем может поделиться; получает объяснимые совпадения и договаривается о 15-минутной встрече. Организатор задаёт интервалы, место и видит агрегаты. Целевой эффект — больше согласованных полезных разговоров; прирост и полезность для аудитории пока не измерены.

2. Процесс

Регистрация → скрытый профиль → темы и будущее время → добровольная публикация → подбор с причиной совпадения → приглашение → согласие получателя → одинаковые тема, время и место у обоих → личная обратная связь после окончания. Общение и обмен контактами проходят офлайн; контакты сервис не собирает.

3. Реализованный объём

  • Вход по логину/паролю и серверная HttpOnly-сессия; новый профиль скрыт.
  • Редактирование запроса, опыта и доступности; поиск и фильтр тем.
  • Детерминированные рекомендации: совпадение запроса с опытом и общий свободный будущий интервал.
  • Приглашения, принятие, отказ, отмена, собственная оценка после встречи.
  • Атомарное резервирование времени обоих участников; занятый слот исключается из подбора.
  • Панель организатора: интервалы по 900 секунд без пересечений, агрегированные показатели.
  • Опубликованный лендинг из четырёх блоков: ценность; анимация совпадения; участники; регистрация/карточка. Прокрутка обратима, на границах есть остановки, reduced motion отключает движение.

Не входят чат, email/SMS, билетная авторизация, восстановление пароля, календарные интеграции и подтверждение квалификации. Восстановление пароля явно обозначено как недоступное. Контактные данные не запрашиваются.

4. Архитектура и развёртывание

Два отдельных публичных репозитория и два сервиса. Next.js/TypeScript отвечает за интерфейс и транспортный /api/* proxy; FastAPI — за права, валидацию и бизнес-правила. SQLite/SQLAlchemy и Alembic хранят семь таблиц. Подбор не требует LLM. API_BASE_URL читается сервером Next.js во время запроса.

Вход: scrypt, HttpOnly/SameSite сессия, Secure cookie в production; изменяющим запросам нужен CSRF-заголовок и допустимый Origin. Публикация требует темы и будущего времени. Accepted создаёт две bookings в одной транзакции; pending ничего не резервирует. Удаление профиля каскадно удаляет связанные встречи у обеих сторон.

Production доставлен ZIP-архивами в GitRelax/RelaxDev. Пуш в GitHub сам по себе не обновляет эти контейнеры. При переносе дизайна исправлено копирование public в Docker runner; после пользовательской пересборки фото доступно по HTTP 200.

5. Проверки

21 ноября на production проверены регистрация и её валидация, согласие, скрытый профиль по умолчанию, сохранение сессии после reload, выход и повторный вход, удаление временного тестового аккаунта. Отдельно созданные Иван, Эльдар и Таисия оставлены по поручению пользователя.

Организатор добавил четыре слота 13:00–14:00 МСК у стойки регистрации. У трёх тестовых аккаунтов сохранена доступность и включена видимость. Через настоящий интерфейс Иван пригласил Эльдара на 13:00–13:15 по теме «ИИ в аналитике»; Эльдар принял в отдельной сессии. API обоих аккаунтов подтвердил accepted, в интерфейсе совпали тема, время и место. Занятый слот исключён из рекомендаций. Интервал тестовой встречи уже прошёл; повтор требует будущего времени.

Повторные публичные чтения подтвердили сайт, изображение, health, Swagger и контракт. Живой OpenAPI совпадает с локальным: 15 операций. На ширинах 320–1440 px нет горизонтального переполнения. Подтверждены остановки секций, замирание/обратимость сцены, переход к форме и возврат в начало.

Локально повторно пройдены 25 API-тестов на изолированной БД, 10 тестов прокси и TypeScript; production build пройден после интеграции. Старый GitHub CI подтверждал прежние коммиты и не приравнивается к новой версии. Текущие доказательства и ограничения собраны в комплекте сдачи.

6. Ограничения

Сохранность SQLite после полного пересоздания backend-контейнера RelaxDev, постоянный volume /data и резервное копирование не подтверждены. Один worker и один экземпляр; rate limit в памяти процесса. Локально Docker CLI отсутствует; исправление доставки изображения подтверждено production HTTP-чтением, а не локальным запуском контейнера.

Именованные тестовые аккаунты созданы обычной регистрацией, у них is_demo=false, поэтому они и тестовая встреча входят в агрегаты. Их нельзя использовать как результат пилота. Для пилота нужны отдельный срез/среда, реальные добровольцы и будущие слоты. Числовой эффект пока не заявляется.

Видео исключено пользователем. Отправка финальной формы организаторам не выполнялась. Готовность исходников, документов и ZIP не означает завершённую сдачу.
