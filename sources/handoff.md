# Ссылки и порядок сдачи

Подготовлено по [требованиям организаторов](https://ad23-hackathon-info.website.yandexcloud.net/artifacts/). Видео исключено пользователем. Ссылки передаются в единую форму до 12:00 второго дня по инструкции организаторов; это требование страницы, а не подтверждение своевременной отправки. Прямой ссылки на форму на странице нет.

## Единый архив

`got-a-topic-submission.zip` содержит весь `submission/`: HTML и навигацию, источники, схемы, OpenAPI, снимки, сценарий речи, доказательства и два исходных кодовых архива. После распаковки открыть `index.html`. Контрольная сумма — в соседнем файле `.sha256`, внутренние SHA-256 — в `manifest.json`.

Исходники: [frontend-source.zip](../code/frontend-source.zip), [backend-source.zip](../code/backend-source.zip). Их происхождение описано в [release-provenance.json](../evidence/release-provenance.json). Внутри архивов есть README и Dockerfile. Исходники не содержат .env, паролей участников, сессий, SQLite, node_modules и .git. `.env.example` содержит только пример конфигурации.

## Публикация документов

Загрузить ZIP и распакованный `submission/` в облачную папку с открытым чтением и скачиванием. Проверить доступ без авторизации. Если просмотрщик не исполняет HTML, документы читаются в `sources/`, а навигация работает после скачивания ZIP. Для просмотра прямо в браузере разместить содержимое `submission/` на GitHub Pages; `.nojekyll` уже включён.

Публичные репозитории кода не заменяют ссылку на документы в GitHub Pages/облачном диске. Комплект не считается опубликованным только потому, что файлы собраны локально. Отправка формы этим действием не выполняется.

## Показ демо

[Речь в порядке четырёх блоков](demo-script.md), [порядок проверки встречи](acceptance.md). Пароли оставленных тестовых аккаунтов находятся только у владельца в отдельном локальном файле и в материалы не включаются. Для нового назначения нужны будущие интервалы; историческую тестовую встречу можно показать в «Моих встречах».

Продуктовый эффект не измерен. Сохранность SQLite при полном пересоздании backend на RelaxDev не подтверждена. Обновление frontend не требует пересборки backend. Не проверять постоянство данных разрушительным редеплоем без резервной копии.
