# Бизнес-потребность и измеримый эффект

## Пользователь и ценность

Участник конференции приходит с профессиональными вопросами и собственным опытом. «Есть тема» помогает найти взаимный повод для разговора и договориться о конкретных времени и месте. Организатор получает инструмент поддержки знакомств и агрегированные сигналы об их результате.

Гипотеза проблемы: случайное знакомство не всегда приводит к полезному разговору, поскольку заранее неизвестны темы и доступность собеседника. Исходная частота проблемы, спрос и готовность участников заполнять профиль не измерены.

## Механизм эффекта

Запрос и опыт структурированы темами. Рекомендация объясняет совпадение, показывает общий свободный интервал и позволяет отправить приглашение. Встреча назначается только по согласию. После окончания обе стороны независимо отвечают, состоялся ли разговор и был ли он полезен.

## Реализованные метрики

Источник — `GET /api/admin/stats`, функция `stats` в backend. Зерно: текущее состояние одной конференции в одной БД на момент запроса. Исторические срезы и когортный анализ не реализованы. Демо-профили и приглашения с их участием исключаются; реальные организаторские и ручные тестовые аккаунты автоматически не исключаются.

| Показатель API | Точное определение |
| --- | --- |
| profiles | Число текущих пользователей с `is_demo=false` |
| active_profiles | Видимые недемо-профили с непустыми wanted или offered и непустой availability; будущность слотов здесь повторно не проверяется |
| participants_with_meeting | Уникальные участники приглашений в текущем статусе accepted, пересечённые с active_profiles; прошедшие accepted тоже учитываются |
| invitations | Все текущие приглашения, обе стороны которых входят в недемо-пользователей |
| ever_accepted | Приглашения с непустым accepted_at, в том числе позднее отменённые |
| cancelled_after_accept | Приглашения со статусом cancelled и непустым accepted_at |
| confirmed_meetings | Приглашения с двумя happened=true; это взаимное подтверждение факта, а не проверка полезности обеими сторонами |
| positive_ratings / ratings | Число useful=true / число отзывов с useful не null; зерно — один отзыв одного участника |
| feedback_responses | Все отзывы по учитываемым приглашениям, включая happened=false |
| topics[].participants | Видимые недемо-пользователи с темой в wanted или offered; на пользователя тема считается один раз |

## Как измерить результат пилота

| Метрика | Расчёт и ограничение |
| --- | --- |
| Охват назначенными встречами | participants_with_meeting / active_profiles; оба числа из одного среза |
| Доля когда-либо принятых приглашений | ever_accepted / invitations; отменённые после принятия остаются в числителе |
| Полезность полученных оценок | positive_ratings / ratings; не представляет мнения не ответивших |
| Взаимно подтверждённые разговоры | confirmed_meetings; абсолютный результат среди сохранившихся записей |
| Охват обратной связью | Для корректного знаменателя нужны завершившиеся встречи и допустимые ответы; отдельного готового счётчика нет |

При нулевом знаменателе доля не определена. Нельзя подменять её нулевым успехом или рассчитывать охват отзывами как feedback_responses / (2 × ever_accepted): туда попадут будущие и отменённые встречи.

До пилота организатор согласует интервал наблюдения, реальные слоты, добровольцев и способ отделить ручные тестовые аккаунты. Предлагаемый критерий первого пилота — получить взаимные подтверждения реальных разговоров и проверить, понятны ли подбор и согласование времени. Числовые целевые значения и сравнение с исходным процессом ещё не согласованы; прирост не заявляется.

Удаление профиля удаляет связанные приглашения и отзывы, поэтому последующие агрегаты могут уменьшаться. Для длительного измерения нужны согласованные обезличенные срезы и правила хранения. Текущие тесты показывают техническую работоспособность, а не измеренный бизнес-эффект.

## Ограничение текущего теста

21 ноября созданы Иван, Эльдар и Таисия через обычную регистрацию. Это явно помеченные в описании тестовые профили, но у них `is_demo=false`; поэтому их записи и тестовая встреча Иван ↔ Эльдар входят в текущие агрегаты. Эти значения нельзя выдавать за метрики реального пилота. Для пилота требуется отдельная среда/срез или явный фильтр тестовых записей.
