ТЗ Backend · Есть тема

Самостоятельный HTTP-сервис, FastAPI; все пути /api/*. Структура данных и процесс — архитектура и ERD. OpenAPI генерируется приложением, Swagger /api/docs. Ответы всех операций описаны Pydantic-моделями в app/schemas.py; экспорт OpenAPI — в openapi.json. Ошибки: {"error":{"code":409,"message":"…"}}; при валидации дополнительно безопасный список полей без входных паролей.

API

Метод Путь Назначение / доступ
GET /api/health Живость и SELECT 1
GET /api/config Справочник тем, интервалы и флаг демо
POST /api/auth/register Логин 3–32 ASCII-символа, пароль 10–128, имя; скрытый профиль, cookie, 201
POST /api/auth/login Проверка scrypt, новая случайная сессия
POST /api/auth/logout Удаление текущей сессии и cookie
GET / PUT / DELETE /api/me Собственный профиль, изменение, удаление
GET /api/recommendations До 30 объяснимых рекомендаций для опубликованного профиля
POST /api/invitations Получатель, слот, общая тема, сообщение ≤300; 201
GET /api/invitations Только собственные приглашения, текущий статус и собственная оценка
POST /api/invitations/{invitation_id}/action action: accept / decline / cancel
PUT /api/invitations/{invitation_id}/feedback happened: bool, useful: bool/null
POST /api/admin/slots Организатор: будущий непересекающийся интервал 900 секунд
GET /api/admin/stats Организатор: агрегаты без демо-профилей и их встреч

Изменяющие методы требуют X-Requested-With: pereryv, допустимый Origin при наличии. CORS только из FRONTEND_URL. Swagger Authorize позволяет указать значение заголовка. Cookie HttpOnly, SameSite=Strict, Secure в production, TTL 7 дней; в БД хранится SHA-256 токена. Неуспешный вход одинаково отвечает для несуществующего пользователя и неверного пароля.

Примеры

Создать приглашение: {"recipient_id":2,"slot_id":1,"topic_id":1,"message":"Обсудим опыт внедрения?"}. Ответ: {"id":1,"status":"pending"}.

Профиль PUT: {"name":"Анна","role":"Аналитик","company":"","bio":"Хочу обменяться опытом","wanted":[1],"offered":[2],"availability":[1],"visible":true}. Каждый список тем ≤5, доступность ≤20. Неизвестные темы и прошедшие интервалы отклоняются.

401 — нет сессии; 403 — запрещён источник/роль/действие отправителя; 404 — чужое или отсутствующее приглашение; 409 — повтор, конфликт времени или недопустимый переход; 422 — некорректные данные; 429 — ограничение частоты с Retry-After; непредвиденные 500 — безопасный JSON без технических деталей.

Подбор

3 × число тем «мой запрос / опыт другого» + 2 × «мой опыт / запрос другого» + число оставшихся общих тем. Требуется положительный балл и общий будущий незанятый слот. Сортировка по убыванию балла, затем id. Причина раскрывает идентификаторы тем, не квалификацию. Собственные/скрытые/уже встречавшиеся по принятому приглашению исключаются.

Приёмка и ограничения

Права и данные проверяются сервером. Повтор принятия идемпотентен для того же получателя. Конкурирующие принятия на один слот дают одну встречу. Отмена удаляет занятость. Приглашать себя, использовать чужой слот, тему без совпадения, отвечать за другого нельзя. Повторное приглашение тому же человеку ограничено часом, отправка — 10/минуту на пару «адрес + аккаунт», вход — 10/минуту на пару «адрес + логин», регистрация — 30/минуту на адрес. За прокси регистрационные лимиты могут объединять пользователей; настройку шлюза уточнить до массового пилота. Лимиты одного процесса не заменяют шлюз при масштабировании.

Удаление каскадное; индивидуальные контакты не собираются. SQLite требует постоянного диска, одного экземпляра и worker. Наличие постоянного диска в RelaxDev не подтверждено. Времена хранятся как Unix UTC, интерфейс показывает Europe/Moscow. Проверки доступа, гонок, отмены, обратной связи и удаления — pytest.

Диагностика

Каждый запрос записывается структурной JSON-строкой: время UTC, метод, шаблон маршрута, статус, длительность, Content-Length при наличии, код ошибки. Query string, тело запроса, токены и персональные данные не логируются. Uvicorn access log отключается при запуске через Docker и dev-скрипт.
